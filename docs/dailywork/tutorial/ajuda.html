O próximo passo, explicado.

Três orientações para acompanhar o tutorial quando a instalação, a pasta de notas ou o registro de evidências precisarem de um ajuste.

01 / Primeiros passos

Comece na pasta do aplicativo.

Se o DailyWork já está instalado, use o atalho recebido. Os comandos abaixo são para quem tem acesso a uma cópia do projeto e vai preparar o aplicativo nessa máquina.

  1. Abra um terminal na raiz da cópia do projeto. Entre na subpasta Daily Work app, que contém o arquivo package.json.
  2. Com Node.js e npm instalados, instale as dependências e abra o aplicativo:
cd "Daily Work app"
npm install
npm run app

Se o terminal já está dentro de Daily Work app, comece em npm install. O comando npm run app gera a versão desktop e a abre.

Instalar os atalhos

Na mesma pasta, use o comando da sua plataforma:

# Linux
npm run install:linux

# Windows, no ambiente da instalação
npm run install:windows

Esta vitrine não distribui um instalador público nem dá acesso ao repositório privado. Recursos de inteligência artificial também precisam do provedor configurado na instalação.

02 / Suas fontes

Conhecimento lê uma pasta de notas.

O leitor do aplicativo mostra as notas da pasta configurada na instalação. Por padrão, ele procura LucasOL/Knowledge ao lado da pasta Daily Work app. O leitor não tem um campo para escolher outra pasta.

  1. Confira se a pasta de conhecimento existe e contém suas notas Markdown.
  2. Se as notas estão em outro lugar, indique o caminho completo na variável LUCAS_KNOWLEDGE_DIR ao iniciar o aplicativo.
  3. Abra o Principal, escolha Conhecimento e pesquise uma nota pelo título. Ao editar uma nota, use Salvar para gravar a fonte.

Exemplo no Linux

Dentro de Daily Work app, substitua o caminho de exemplo pela pasta das suas notas:

LUCAS_KNOWLEDGE_DIR="/caminho/para/minhas-notas" npm run app

Exemplo no Windows PowerShell

$env:LUCAS_KNOWLEDGE_DIR = "C:\caminho\para\minhas-notas"
npm run app

Esses exemplos configuram a execução iniciada pelo terminal. Para usar sempre essa pasta pelo atalho, a configuração também precisa estar no ambiente de inicialização do atalho. O aplicativo deve ser iniciado com a variável já definida.

03 / Fechar com um resultado verificável

Registre o que comprova a entrega.

Uma frente concluída precisa de referências reais para entrar na contagem de resultados com evidência: por exemplo, o arquivo entregue, um link de resultado e uma verificação realizada.

Nesta versão, o fechamento consulta a lista evidencias no cabeçalho Markdown da frente. Escrever uma referência apenas no corpo do texto não preenche essa lista. O executor nativo pode registrá-la ao finalizar uma execução; a conversa comum com o Agente ainda não edita esse campo.

  1. Na instalação padrão, encontre o arquivo da frente em data/dias/AAAA-MM-DD/, dentro da pasta do aplicativo e usando a data em que o trabalho está registrado. Se a instalação usa outra pasta de dados, procure o mesmo diretório dias nela. Abra o arquivo que contém o título da frente.
  2. Dentro do cabeçalho entre os dois delimitadores ---, acrescente ou atualize a lista abaixo, preservando os demais campos. Troque os exemplos por referências e resultados que você realmente conferiu.
evidencias:
  - entregas/boas-vindas.html
  - Validação: página abriu sem erro

A linha evidencias: fica sem valor ao lado. Cada item vai na linha seguinte, com dois espaços, um hífen e um espaço. Use esse formato de lista; o leitor desta versão não interpreta listas entre colchetes na mesma linha.

  1. Salve o arquivo no editor. O DailyWork acompanha as alterações dos seus arquivos.
  2. Volte à data da frente e abra novamente Revisar fechamento. Confira o resultado e a contagem de frentes sem evidência antes de confirmar os destinos.

Registrar a referência não executa a verificação por você. Confira a entrega primeiro e descreva somente o resultado observado. O fechamento salva os destinos locais selecionados; publicar no site ou em uma conta externa é uma ação separada.
